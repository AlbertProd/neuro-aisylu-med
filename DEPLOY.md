# Размещение НейроАйсылу

Бот использует Telegram polling. Ему нужен один постоянно работающий процесс и постоянный диск для SQLite. Публичный домен и входящий HTTP-порт не требуются. Запускай только один экземпляр с одним токеном.

## Переменные окружения

Скопируй `.env.example` в `.env` и укажи собственные значения:

- `TELEGRAM_BOT_TOKEN` — токен своего бота из BotFather.
- `POLZA_API_KEY` — свой ключ Polza AI.
- `OWNER_USER_ID` — числовой Telegram ID владельца; предпочтителен для первого запуска.
- `OWNER_USERNAME` — свой Telegram ник для первоначальной привязки, если ID не указан.
- `DATABASE_PATH` — путь к базе на постоянном диске, например `/app/data/aisylu.sqlite`.
- `DAILY_BUDGET_RUB` — общий дневной бюджет; по умолчанию 100 ₽ по времени Уфы.

Остальные настройки, включая модель и ограничения поиска/медиа, описаны в `.env.example`. У провайдера может действовать отдельный, более строгий лимит. Ключи вводи через защищённые переменные хостинга или локальный `.env`, не добавляй их в репозиторий, архив кода или образ.

## Docker

Dockerfile рассчитан на Linux amd64/arm64, использует Node.js 24, встроенный SQLite и системный FFmpeg. Рабочий код хранится в `/opt/aisylu`, постоянная база — в `/app/data`.

```sh
docker build -t neuro-aisylu .
docker run -d --name neuro-aisylu --restart unless-stopped \
  --env-file .env \
  -e DATABASE_PATH=/app/data/aisylu.sqlite \
  -v "$PWD/data:/app/data" \
  --memory 768m --cpus 1 \
  --log-opt max-size=10m --log-opt max-file=3 \
  neuro-aisylu
docker logs --tail 30 neuro-aisylu
```

При обновлении останови контейнер, сделай согласованную копию SQLite, собери новый образ и запусти его с тем же постоянным диском. Имя, описание и команды Telegram синхронизируются при изменении. Их успешная версия и пауза `retry_after` сохраняются в SQLite; ошибка обновления профиля не останавливает polling.

## Bothost

1. Выбери тариф и ноду с постоянным хранилищем. Перед размещением проверь текущие условия в [документации Bothost](https://bothost.ru/docs/).
2. Собери архив: `node --env-file-if-exists=.env scripts/package-deploy.js`. Он содержит исходники, тесты и документацию; локальные ключи и база исключены.
3. Загрузи `deploy-artifacts/aisylu-deploy.tar.gz`, укажи Node.js и главный файл `src/index.js`. При поддержке собственного Dockerfile используй приложенный файл.
4. Добавь свои переменные окружения и `DATABASE_PATH=/app/data/aisylu.sqlite`.
5. Если платформа генерирует стандартный образ Node.js 20.20, оставь `FFMPEG_PATH` и `FFPROBE_PATH` пустыми. Зависимости содержат статические FFmpeg/FFprobe, а `src/sqlite.js` использует `better-sqlite3`, когда встроенный SQLite отсутствует.
6. Для переноса работающего бота сначала останови старый экземпляр, затем перенеси согласованную копию базы и только после этого запускай новый.
7. Проверь строку запуска в журнале, `/status`, `/budget`, ответ в группе и сохранность игр после перезапуска.

Изменения архивного бота отправляй новым архивом: платформа может восстанавливать исходники при пересборке. Папка `/app/data` должна сохраняться при пересоздании контейнера.

## Обычный Linux-сервер

Можно использовать Docker по инструкции выше. Для Ubuntu 24.04 подготовлен `deploy/oci-cloud-init.yaml`: он устанавливает Docker без запуска бота и без хранения ключей. Экземпляр с собственным `.env` и постоянным диском запускается отдельно.

## Резервная копия SQLite

```sh
node --env-file=.env scripts/backup.js data/backups/migration.sqlite
```

Копия согласованная и включает изменения из WAL. Скрипт не перезаписывает существующий файл: выбирай новое имя. Для окончательного переноса сначала останови старый экземпляр, чтобы в копию попали последние сообщения и расходы.

Переноси только полученный SQLite-файл. Файлы `bot.lock`, `-wal` и `-shm` отдельно не нужны. База содержит частную историю чата и переносится через закрытый канал, отдельно от исходного кода.

## Проверка перед публикацией кода

```sh
node --test
node --env-file-if-exists=.env scripts/check-secrets.js
```

Проверка секретов читает содержимое индекса Git, а не только текущие файлы. Она блокирует локальные данные, известные значения ключей из окружения, форматы токенов Telegram/Polza/GitHub и закрытые ключи. Добавляй в Git только исходники, тесты, конфигурацию без секретов и документацию.
